# 对象与外部环境的协作
> 把活动状态保存为 JSON，重新读取并校验，再导出可用于表格软件的 CSV 名单。

## 8.1 关闭报名程序以后，名单在哪里

前几章的活动对象把名单保存在内存中。组织者结束本次工作后，下次打开程序还需要继续使用同一份名单。另一个需求是把名单交给负责签到的同学，在表格软件里查看。

- 输入是一场已登记 `S01`、`S02` 的博物馆活动，容量为 2。
- 保存活动名称、容量和报名顺序。恢复时从保存的记录重新取得这些数据，并验证名额与名单规则。
- 另外生成一份有表头的名单，每位参加者占一行，供表格软件导入。

这两份文件服务于不同任务。恢复时需要保留有名字的字段及其关系，导出时需要有稳定的行和列。先了解 Python 怎样使用文件资源和两种常见的数据格式。

## 8.2 用路径定位外部资源

### 路径怎样指向一个位置

`pathlib.Path` 表示文件系统中的路径。绝对路径从系统规定的位置开始，相对路径通常以当前工作目录为基准。`Path.cwd()` 返回当前工作目录。用 `/` 可以拼接路径段，`path.parent` 取得父目录。若需要创建中间目录，可用 `mkdir(parents=True, exist_ok=True)`。

### 先构造路径，再使用路径

路径对象可以描述一个尚未创建的文件。`path.name` 取得最后一段文件名，`path.suffix` 取得扩展名，`path.stem` 取得去掉最后一个扩展名的名称。拼接路径只是计算位置，创建目录、打开文件是另外的操作。

```python
from pathlib import Path

path = Path("records") / "morning.csv"
print("父目录", path.parent)
print("文件名", path.name)
print("主文件名与扩展名", path.stem, path.suffix)
print("是否为绝对路径", path.is_absolute())
```

示例中的路径是相对的，同一写法在不同工作目录下可能指向不同文件。将目标目录作为参数交给函数，能明确在哪个位置读写。相对路径需要先弄清相对的是哪一个目录，绝对路径则可以直接定位到指定位置。[Python 官方文档的 pathlib](https://docs.python.org/3.12/library/pathlib.html)

## 8.3 选择打开方式并管理文件对象

### 打开文件时声明读写方式

| 模式 | 用途 | 对已有文件的影响 |
| --- | --- | --- |
| `"r"` | 读取，默认模式 | 保留内容，文件必须存在 |
| `"w"` | 写入，可创建新文件 | 打开时截断已有内容 |
| `"a"` | 追加，可创建新文件 | 将新内容加到末尾 |
| `"x"` | 创建新文件并写入 | 已存在时报告错误 |
| `"rb"` 或 `"wb"` | 按字节读写 | 读写规则沿用对应的 `r` 或 `w` |

文本模式负责在字符与字节之间转换，打开文本文件时可以指定 `encoding="utf-8"`。二进制模式直接读写字节。文件对象持有打开的资源，使用 `with` 可以在离开代码块时自动关闭文件，包括块内发生异常的情况。

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "samples" / "notes.txt"
    path.parent.mkdir(parents=True, exist_ok=True)

    with path.open("x", encoding="utf-8") as stream:
        stream.write("第一条观察\n")
    print("文件已关闭", stream.closed)

    with path.open("a", encoding="utf-8") as stream:
        stream.write("第二条观察\n")

    print(path.read_text(encoding="utf-8").splitlines())
```

`TemporaryDirectory` 也由 `with` 管理，离开外层块时清理示例文件。`read_text` 适合一次读取整个小文件，内容较多时可以在打开文件的块内用 `for line in stream` 逐行读。[Python 官方文档的 pathlib](https://docs.python.org/3.12/library/pathlib.html)

### 一次读完与逐行处理

`read_text()` 一次读出完整文本，适合内容较小、后续要整体处理的文件。逐行处理时可以一边读一边累计结果。下面用一条内存文本流演示同样的迭代写法，每轮得到一行带换行符的文字。

```python
from io import StringIO

total = 0
count = 0
with StringIO("18\n\n21\n20\n") as stream:
    for number, line in enumerate(stream, start=1):
        text = line.strip()
        if not text:
            continue
        value = int(text)
        print("第几行、读数", number, value)
        total += value
        count += 1

print("读数的条数和总和", count, total)
```

程序跳过空行，在读取下一行前完成当前行的处理。文件流读到末尾后停止迭代。想从头再读，可以重新打开，或对支持定位的流用 `seek(0)` 回到开头。具体的读数格式应由调用者约定，非法行可以按第 7 章的方法报告。

### with 在正常结束和异常时都执行退出动作

`with` 通过资源对象的进入与退出约定管理资源。文件对象退出时关闭，临时目录退出时清理。嵌套使用时，先离开内层文件块，再离开外层目录块。下面让一个错误发生在读取之后，检查离开代码块时文本流的状态。

```python
from io import StringIO

try:
    with StringIO("无读数") as stream:
        value = int(stream.read())
except ValueError as error:
    print("转换失败", type(error).__name__)
    print("流是否已经关闭", stream.closed)
```

异常传播到 `except` 前，`with` 已完成关闭动作。把使用文件的代码放在 `with` 内，将需要交给后续步骤的值保留为普通对象，就能清楚区分文件的使用期限和数据的使用期限。[Python 官方教程的文件读写](https://docs.python.org/3.12/tutorial/inputoutput.html#reading-and-writing-files)

## 8.4 理解字符、字节和编码

文件中保存的是字节。按文本打开时，Python 依据指定的编码在字符和字节之间转换。用 `encoding="utf-8"` 明确约定，可以让写入和读取使用同一种编码。按二进制打开时，`read()` 得到字节序列，解释这些字节的工作交给后续步骤。

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "note.txt"
    path.write_text("东站", encoding="utf-8")
    data = path.read_bytes()
    print("保存的字节数", len(data))
    print("按 UTF-8 解读", data.decode("utf-8"))
    try:
        print(data.decode("ascii"))
    except UnicodeDecodeError:
        print("ASCII 无法解释这些字节")
```

“东站”是两个字符，UTF-8 保存为六个字节。相同的字节交给不同解码规则，可能产生错误或不同文字。读到 `UnicodeDecodeError` 时，先核对实际保存的编码，再选择相应的解码方式。

## 8.5 用 JSON 保存结构化数据

JSON 把结构化数据写成文本。Python 的字典、列表、字符串、数字、布尔值和 `None` 可转换为对应的 JSON 对象、数组、字符串、数值、真假和 `null`。交换数据时宜使用字符串作为字典键，并事先约定必需字段与类型。

| JSON 中的数据 | 读取为 Python 对象 | 保存时常用的 Python 对象 |
| --- | --- | --- |
| 对象 | `dict` | 用字符串字段名组织的字典 |
| 数组 | `list` | 列表，或可以转成数组的元组 |
| 字符串 | `str` | 字符串 |
| 数字 | `int` 或 `float` | 整数、有限的浮点数 |
| `true`、`false` | `True`、`False` | 布尔值 |
| `null` | `None` | 缺失值 |

```python
import json

reading = {"地点": "东站", "温度": [18, 20], "已复核": True, "备注": None}
text = json.dumps(reading, ensure_ascii=False, indent=2)
print(text)

restored = json.loads(text)
print(restored["温度"][0], restored["已复核"])
```

`dumps` 和 `loads` 处理字符串，`dump` 和 `load` 处理打开的文件对象。`ensure_ascii=False` 让生成的文本直接显示中文，`indent=2` 便于阅读。自定义对象通常要先挑出要保存的字段，组成可序列化的数据。读取后再根据这些字段恢复对象或供其他组件使用。[Python 官方文档的 json](https://docs.python.org/3.12/library/json.html)

### 约定能保存什么，以及怎样恢复

JSON 主要保存数据关系。用元组表示的位置在 JSON 里会成为数组，读取后得到列表。如果应用还要求位置固定为两个数，就应校验长度，再按需要恢复成元组。对象的方法和内部状态的更新规则由 Python 中的定义提供。

```python
import json

original = {"position": (3, 4), "visible": True, "note": None}
wire = json.dumps(original, ensure_ascii=False)
restored = json.loads(wire)

print("交换文字", wire)
print("位置字段读为", type(restored["position"]).__name__)
position = tuple(restored["position"])
print("应用需要的坐标", position)
```

可读性选项控制输出的文字形式。`indent=2` 帮助查阅，紧凑表示更节省空间。程序应依据字段及其值来解析数据。读写前明确字段名称、类型、取值范围和相互关系，才能判断一份记录是否能恢复成可使用的对象。

## 8.6 用 CSV 交换表格数据

CSV 以记录表示行，以字段表示列。可以用 `csv.writer` 和 `csv.reader` 逐行处理，也可以用 `DictWriter` 和 `DictReader` 按列名组织数据。字段内有逗号、引号或换行时，模块会按规则处理转义和引用。

```python
import csv
from io import StringIO

stream = StringIO(newline="")
writer = csv.DictWriter(stream, fieldnames=["地点", "读数"])
writer.writeheader()
writer.writerow({"地点": "东站, 门口", "读数": 18})

print(stream.getvalue().strip())
stream.seek(0)
row = next(csv.DictReader(stream))
print(row["地点"], int(row["读数"]) + 1)
```

`StringIO` 是内存中的文本流，可以像文件一样读写。写完后用 `seek(0)` 回到开头。上例中带逗号的地点保留在同一列，读数读取时仍是字符串，需要计算时再转换。用真实文件读写 CSV 时传入 `newline=""`，由 `csv` 管理记录的换行。[Python 官方文档的 csv](https://docs.python.org/3.12/library/csv.html)

### 表头、字段文字和类型转换

使用 `csv.DictReader` 时，第一行通常是表头，之后每一行按照列名交出字段。字段值默认是文字。数量要转换成数字，带前导零的编号则应保留原样。

```python
import csv
from io import StringIO

source = StringIO("编号,件数\n0007,2\n0009,0\n", newline="")
reader = csv.DictReader(source)
total = 0
for row in reader:
    code = row["编号"]
    count = int(row["件数"])
    print("编号和件数", code, count)
    total += count

print("总件数", total)
```

数据来自外部时，还要核对表头是否包含必需列，空字段能否解释，转换后的数量是否在允许范围。导入表格软件时，可以将编号列指定为文本，以保留前导零。需要保存嵌套结构时，可以用 JSON 保存完整记录，再从同一数据生成用于浏览的 CSV。

## 8.7 在边界区分缺失、格式错误与非法数据

能打开文件、能解析格式、数据符合应用约定，是三个要分别验证的条件。例如，JSON 能把 `{"quantity": -1}` 解析为字典，使用库存数据的程序还需检查数量是否合法。

| 情形 | 可能出现的异常 | 调用者如何使用这个信息 |
| --- | --- | --- |
| 路径没有对应的文件 | `FileNotFoundError` | 首次启动时可按约定建立初始状态 |
| 当前操作没有足够权限 | `PermissionError` | 报告哪个资源无法访问 |
| 字节无法按指定编码解读 | `UnicodeDecodeError` | 确认文件编码，保留原文件供检查 |
| JSON 文本格式有误 | `json.JSONDecodeError` | 报告文件内容无法解析 |
| 数据类型或取值违反业务规则 | 校验函数报告的 `ValueError` | 报告具体字段或规则 |

### 只有确实缺失时才启用初始数据

首次启动和已有数据损坏是两种不同的情况。可以在读文件这一小段操作上捕获 `FileNotFoundError`，用默认状态继续。成功取得文字后，再解析内容。格式错误应交给调用者报告。

```python
import json
from pathlib import Path
from tempfile import TemporaryDirectory


def load_readings(path):
    try:
        content = path.read_text(encoding="utf-8")
    except FileNotFoundError:
        return {"values": []}
    return json.loads(content)


with TemporaryDirectory() as folder:
    path = Path(folder) / "readings.json"
    print("首次启动", load_readings(path))

    path.write_text("{损坏", encoding="utf-8")
    try:
        print(load_readings(path))
    except json.JSONDecodeError:
        print("原文件需要检查", path.read_text(encoding="utf-8"))
```

这一步只能保证得到可解析的数据。若返回值要参与计算，还应确认是字典、存在 `values` 字段、字段是列表、每项读数符合约定。比如 `{"values": "18"}` 能成功解析，仍然无法按期望处理多条读数。

## 8.8 让保存失败保留可恢复的旧数据

### 把写完和替换分成两个步骤

打开已有文件时选择 `"w"` 会立即截断文件。如果新内容写到一半出现异常，旧内容可能已经丢失。更新正式数据时，可以在同一个目录先写临时文件，完成序列化并关闭后再替换目标。失败时清理临时文件，把原来的错误交给调用者。

```python
import json
from pathlib import Path
from tempfile import NamedTemporaryFile, TemporaryDirectory


def write_snapshot(path, data):
    pending = None
    try:
        with NamedTemporaryFile(
            mode="w", encoding="utf-8", dir=path.parent, delete=False
        ) as stream:
            pending = Path(stream.name)
            json.dump(data, stream, ensure_ascii=False)
        pending.replace(path)
    finally:
        if pending is not None:
            pending.unlink(missing_ok=True)


with TemporaryDirectory() as folder:
    path = Path(folder) / "snapshot.json"
    write_snapshot(path, {"values": [18]})
    before = path.read_text(encoding="utf-8")
    try:
        write_snapshot(path, {"values": {18, 20}})
    except TypeError:
        print("序列化失败，保留原内容", path.read_text(encoding="utf-8") == before)
    write_snapshot(path, {"values": [18, 20]})
    print("完成后的内容", json.loads(path.read_text(encoding="utf-8")))
```

集合没有默认的 JSON 表示，第二次保存会在替换前失败。第三次改用列表，写完后才替换正式文件。这种写法把“构造完整新文件”和“把新文件作为当前数据”分开。第 9 章会将它用于保存活动状态。[Python 官方文档的 tempfile](https://docs.python.org/3.12/library/tempfile.html#tempfile.NamedTemporaryFile)

### 先验证失败后的文件，再改写保存步骤

下面的起点直接打开旧文件写入。请在失败时检查文件内容是否与 `before` 一样。运行看到检查失败后，再用上一段的临时文件办法改写 `save()`。重跑时，集合仍会被拒绝，旧内容应能读回，最后一次合法保存也应生效。

```python file-regression
import json
from pathlib import Path
from tempfile import NamedTemporaryFile, TemporaryDirectory


def save(path, data):
    with path.open("w", encoding="utf-8") as stream:
        json.dump(data, stream, ensure_ascii=False)


def verify_failed_save(path):
    before = path.read_text(encoding="utf-8")
    try:
        save(path, {"values": {18, 20}})
    except TypeError:
        # 比较失败后的文件内容与 before。
        raise NotImplementedError("请先写出旧内容检查")
    else:
        raise AssertionError("应拒绝无法序列化的集合")


with TemporaryDirectory() as folder:
    path = Path(folder) / "readings.json"
    save(path, {"values": [18]})
    verify_failed_save(path)
    print("失败后原文件仍可读取")
    save(path, {"values": [18, 20]})
    assert json.loads(path.read_text(encoding="utf-8")) == {"values": [18, 20]}
    print("文件保存验收通过")
```

:::answer
可写 `assert path.read_text(encoding="utf-8") == before, "旧文件内容发生变化"`。直接打开旧文件时，写入模式已经截断内容。参考上一段的 `write_snapshot()`，让 `save()` 先写完同目录的临时文件，再替换目标，并在退出时清理临时文件。
:::

### 其他外部接口也需要说明交付条件

同样的协作思路也适用于其他外部接口。先约定如何取得资源、结果是什么格式，再判断结果能否进入业务流程。例如，调用网络服务读取数据时，调用方需要处理超时，并校验响应所带的字段。

| 协作步骤 | 读取文件 | 向服务请求数据 |
| --- | --- | --- |
| 指定资源 | 文件路径 | 地址与查询条件 |
| 取得内容 | 文本或字节 | 响应状态和内容 |
| 解释数据 | 解码、解析 JSON 或 CSV | 根据约定的格式解析响应 |
| 检查与使用 | 校验字段后恢复状态 | 校验字段后继续业务步骤 |
| 处理失败 | 区分缺失、权限和坏数据 | 区分超时、失败状态和坏数据 |

可以先用已知的样本文字验证解析，再接上外部读取。这会让测试依赖可控的输入，出错时也能区分是没有拿到内容，还是内容不符合约定。

## 8.9 回到案例 保存、恢复并导出报名名单

JSON 使用 `title`、`capacity` 和 `students` 三个字段。名单保留原报名顺序。恢复时检查标题、容量及每个学号，确认没有重复且人数不超限。CSV 从恢复后的数据生成，列名为“活动名称”和“学号”。

| 处理步骤 | 接收的内容 | 交给下一步的结果 |
| --- | --- | --- |
| 保存 | 已校验的活动记录 | 一份 JSON 文件 |
| 恢复 | JSON 文本 | 符合规则的活动数据 |
| 导出 | 恢复后的报名顺序 | 一份有表头的 CSV |
| 核对 | CSV 字段 | 与恢复名单相同的学号顺序 |

校验函数供写入和恢复两条路径使用。写入新文件前先验证原始数据，恢复时先解析再验证，避免把不合规则的内容交给导出功能。

```python
import csv
import json
from pathlib import Path
from tempfile import TemporaryDirectory


def validate_event(data):
    required = {"title", "capacity", "students"}
    if not isinstance(data, dict) or not required <= data.keys():
        raise ValueError("活动数据缺少必需字段")

    title = data["title"]
    capacity = data["capacity"]
    students = data["students"]
    if not isinstance(title, str) or not title.strip():
        raise ValueError("活动名称须为非空字符串")
    if type(capacity) is not int or capacity < 0:
        raise ValueError("容量须为非负整数")
    if not isinstance(students, list):
        raise ValueError("名单须为列表")
    for student_id in students:
        if (
            not isinstance(student_id, str)
            or not student_id
            or student_id != student_id.strip()
        ):
            raise ValueError("名单中有格式不正确的学号")
    if len(set(students)) != len(students):
        raise ValueError("名单中有重复学号")
    if len(students) > capacity:
        raise ValueError("报名人数超过容量")
    return data


def load_event(path):
    with path.open(encoding="utf-8") as stream:
        data = json.load(stream)
    return validate_event(data)


def export_roster(event, path):
    with path.open("x", encoding="utf-8", newline="") as stream:
        writer = csv.writer(stream)
        writer.writerow(["活动名称", "学号"])
        for student_id in event["students"]:
            writer.writerow([event["title"], student_id])


event = {"title": "博物馆参观", "capacity": 2, "students": ["S01", "S02"]}
with TemporaryDirectory() as folder:
    json_path = Path(folder) / "event.json"
    csv_path = Path(folder) / "roster.csv"

    validated = validate_event(event)
    with json_path.open("x", encoding="utf-8") as stream:
        json.dump(validated, stream, ensure_ascii=False, indent=2)

    restored = load_event(json_path)
    print("恢复", restored["title"], restored["students"])
    export_roster(restored, csv_path)
    print(csv_path.read_text(encoding="utf-8").strip())

    with csv_path.open(encoding="utf-8", newline="") as stream:
        exported_ids = [row["学号"] for row in csv.DictReader(stream)]
    print("导出顺序与恢复结果一致", exported_ids == restored["students"])

    invalid = dict(restored, students=["S01", "S01"])
    try:
        validate_event(invalid)
    except ValueError as error:
        print("拒绝非法名单", error)
```

运行后能看到恢复的两个学号、CSV 表头和两行数据，以及重复学号被拒绝的消息。示例在网页的一次运行里经历关闭文件和重新打开文件。临时目录会在运行结束时清理。

### 按约定核对读回的数据

CSV 文件中的表头和两行记录能供人查阅。程序还重新读出“学号”列，与 JSON 恢复的顺序比较。修改报名顺序时，两份输出都应反映同一份名单。若把容量改成 1，应在打开新文件前就发现两人超出名额。
