# 对象协作系统的复用与演化
> 把回执发往终端或收集到内存，了解如何在保留报名规则的同时扩展协作方式。

## 10.1 按能力替换对象
第 9 章将存储作为可替换能力。本章用相同思路扩展通知。组织者希望在终端显示回执，测试希望捕获回执进行检查。用 Protocol 写出 send(message) 的接口。只要对象提供兼容的方法，静态类型检查器就能按这个协议看待它。类可以通过继承共享行为，但可替换性来自调用约定和语义的一致。
对象组合适合把一个独立变化的能力交给另一个角色。终端通知和内存通知只共享接口，因此可以分别实现。若将来几类活动共享一套稳定规则，且子类能遵守基类的契约，可以考虑继承，在子类中重写确有差异的行为。评估继承时，用同一组客户端测试检查每种实现。

```python
from typing import Protocol

class Notifier(Protocol):
    def send(self, message: str) -> None: ...

class ConsoleNotifier:
    def send(self, message: str) -> None:
        print(message)

class RecordingNotifier:
    def __init__(self):
        self.messages: list[str] = []

    def send(self, message: str) -> None:
        self.messages.append(message)

def announce(student_id: str, status: str, notifier: Notifier) -> None:
    notifier.send(f"{student_id}：{status}")

recording = RecordingNotifier()
announce("S01", "通过", ConsoleNotifier())
announce("S02", "满员", recording)
print(recording.messages)
```

如果将通知接到报名主流程，先完成保存再通知。通知发送失败时，应报告发送状态并允许重试发送；重新执行报名会先看到已登记的名单，产生重复回执。把“登记状态”和“通知状态”分别记录，调用方才能区分这两项工作。

例如，若签到界面需要精简的活动名称，可以定义一个继承 Activity 的 LabActivity，重写用于显示的 summary 方法。登记容量与重复检查由基类统一维护。所有调用 summary 的代码继续接收字符串，也都可以调用 register。若实验室报名新增资格核验且会经常变化，可以将资格规则独立为对象，把它传给活动或报名服务。

## 10.2 用装饰器复用外围行为
装饰器接收函数并返回替代对象。@report 相当于用 report 处理刚定义的函数，再把结果绑定回原名字。它适合为多个函数统一加入计时或日志。用 functools.wraps 保留原函数名和文档字符串等元数据。编写包装时继续转发参数、返回值和异常，使调用者可以沿用已有契约。

```python
from functools import wraps

def report(function):
    @wraps(function)
    def wrapped(*args, **kwargs):
        result = function(*args, **kwargs)
        print(f"{function.__name__} 完成")
        return result
    return wrapped

@report
def remaining(capacity, count):
    return capacity - count

print(remaining(2, count=1))
```

## 10.3 迭代协议与泛型基础
可迭代对象提供 __iter__，迭代器还提供 __next__ 并在耗尽时抛出 StopIteration。名单对象可以在 __iter__ 中返回 iter(tuple(self._students))，让调用方遍历创建迭代器时的快照。泛型用于描述输入和输出中类型之间的关系。下面的 T 表示任意一种由调用决定的元素类型；给 first 传入字符串序列时，返回类型是 str | None。

```python
from collections.abc import Iterable
from typing import TypeVar

T = TypeVar("T")

def first(values: Iterable[T]) -> T | None:
    return next(iter(values), None)

print(first(["S01", "S02"]))
print(first([]))
```

## 10.4 等待多个通知操作
异步函数用 async def 声明，调用会创建协程对象，用 await 才会等待其结果。多个相互独立的等待任务可交给 asyncio.gather 组织。下面用 sleep 模拟异步通知，本机和网页可分别运行对应的入口。真实网络调用还要明确超时、失败处理和结果记录。

```python
import asyncio
import sys

async def send(student_id):
    await asyncio.sleep(0.02)
    return f"{student_id} 已通知"

async def main():
    notices = await asyncio.gather(send("S01"), send("S02"))
    print(notices)

if sys.platform == "emscripten":
    # 浏览器已经有事件循环。
    __lesson_task__ = asyncio.ensure_future(main())
else:
    asyncio.run(main())
```

gather 返回结果的顺序与传入任务的顺序一致。协程在等待可让出执行权的操作时，事件循环可以推进其他任务。需要大量计算时，应先测量耗时，再选择合适的运行方式。
