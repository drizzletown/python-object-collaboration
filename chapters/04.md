# 第三视角 函数与协作封装
> 用函数接口描述一项能力，分别验证单次登记、批量处理和回执生成。

## 4.1 为登记函数写契约
第 3 章的一段循环负责清理输入、判断资格、登记和输出。如果以后还要在另一份名单上执行同样的登记，就需要把核心处理定义为函数。先约定 register 的输入为学号文本、现有名单和非负容量。返回回执字符串。仅在通过时修改传入名单。调用方决定怎样显示回执。这份约定说明函数接收什么、返回什么、改变什么，是可以测试的契约。
def 定义函数，形参在调用时绑定到实参对象。传入可变字典时，修改字典的内容可以被调用方观察到。把形参重新赋值为另一个字典只会改变函数内部的绑定。return 结束调用并交出结果，省略 return 时结果为 None。

```python
def register(raw_id, roster, *, capacity):
    student_id = raw_id.strip()
    if not student_id:
        return "空学号"
    if student_id in roster:
        return "重复"
    if len(roster) >= capacity:
        return "满员"
    roster[student_id] = "已报名"
    return "通过"

def process(requests, roster, *, capacity=2):
    for raw_id in requests:
        status = register(raw_id, roster, capacity=capacity)
        print(raw_id.strip() or "（空白）", status)

museum = {}
process(["S01", "S02", "S01", "S03"], museum)
print(list(museum))
```

这里先把 register 当作具备约定行为的能力，写出 process，再独立检验 register 的四种结果。这个做法把假设落实到函数边界。参数列表中的 * 使 capacity 只能通过关键字传递，调用时单位和含义更容易辨认。默认值在定义函数时求值，应避免用空列表或空字典作为每次调用需要重新创建的默认值。需要时使用 None，在函数内部创建容器。

## 4.2 作用域与函数对象
函数内部定义的名字通常只在该次调用的局部作用域有效。内部函数可以引用外层函数的局部名字，并在外层函数返回后继续使用这个绑定，这就是闭包。下面让不同的活动各自得到一个格式化函数。format_all 只需要调用传进来的能力，活动前缀由创建它的地方决定。

```python
def make_formatter(event_name):
    def format_notice(student_id):
        return f"{event_name}：{student_id} 已登记"
    return format_notice

def format_all(ids, formatter):
    return [formatter(student_id) for student_id in ids]

museum_notice = make_formatter("博物馆")
print(format_all(["S01", "S02"], museum_notice))
```

函数可以像其他对象一样被赋值、传入和返回。注意区分 format_notice（传递函数）和 format_notice("S01")（调用并取得字符串）。函数读取自由变量时，使用的是调用时该名字关联的对象。此处每次 make_formatter 调用都有自己的 event_name 绑定。

## 4.3 按需产生结果
批量读取很多记录时，可以边处理边产生结果。含 yield 的函数在被调用时返回生成器。每次迭代推进到下一个 yield，暂停时保留局部状态。迭代耗尽后，要重读需创建新的生成器。

```python
def cleaned_ids(raw_ids):
    for raw_id in raw_ids:
        student_id = raw_id.strip()
        if student_id:
            yield student_id

ids = cleaned_ids([" S01 ", "", "S02"])
print(next(ids))
print(list(ids))
print(list(ids))
```
