# 多对象协作与程序组织
> 组织活动查询与报名服务，用接口、类型标注和模块说明各角色怎样协作。

## 6.1 收到活动编号后，谁负责找到对象

第 5 章可以直接拿着 `museum` 或 `lab` 对象办理报名。真正收到的请求通常只有活动编号和学号，例如 `("museum", "S01")`。程序要先把编号对应到活动，再请该活动决定是否接受请求。

- 输入是若干已开放的活动，以及包含活动编号和学号的报名请求。
- 找到活动时，沿用活动自己的空学号、重复和容量规则。找不到活动时，返回“活动不存在”。
- 输出是每次请求的回执。查询未知编号后，已有活动的名单应保持原样。

从接收请求到给出回执，中间有查找、更新状态和呈现结果几项工作。把这些工作分给不同角色，才能独立调整查询方式或展示方式。

这项任务还有两种不同的变化。活动规则可能增加一个资格条件，查找方式则可能从字典换成别的来源。先分清哪些结果需要跨过职责边界，再决定由谁持有数据、由谁组织调用。

## 6.2 组合对象与约定接口

当一个对象持有另一个对象并通过其公开操作完成一部分工作，就形成了对象组合。例如，一个补货检查器接收库存查询对象。它只需知道查询操作的名字、需要提供的参数、会交出的结果。创建检查器时把所需对象传进去，就可以让调用者选择它使用哪一份库存数据。

```python
class Stock:
    def __init__(self, quantities: dict[str, int]):
        self._quantities = dict(quantities)

    def quantity(self, code: str) -> int | None:
        return self._quantities.get(code)


class ReorderCheck:
    def __init__(self, stock: Stock, minimum: int):
        self._stock = stock
        self._minimum = minimum

    def check(self, code: str) -> str:
        quantity = self._stock.quantity(code)
        if quantity is None:
            return "无此货品"
        if quantity < self._minimum:
            return "需要补货"
        return "库存足够"


check = ReorderCheck(Stock({"P1": 0, "P2": 8}), minimum=3)
for code in ["P1", "P2", "P3"]:
    print(code, check.check(code))
```

`quantity` 的接口约定是接收货品编号，返回非负整数，找不到时返回 `None`。检查器拿到 0 时会继续判断是否补货，拿到 `None` 时直接返回“无此货品”。使用接口时，除了记住方法名，还要明确如何解释返回值、调用是否改变状态、什么情况需要报告失败。

依赖方向可以沿着调用关系看出。检查器请求库存对象提供数量，库存对象可以独立使用。测试时可以构造一份只有一两项的库存，覆盖零库存、正常库存和未知编号。

### 先定职责，再定交接方式

| 要明确的内容 | 用库存查找举例 |
| --- | --- |
| 谁持有原始数据 | 库存对象持有编号和数量的映射 |
| 谁发出请求 | 补货检查器传入一个编号 |
| 成功时交出什么 | 一个非负整数，可能为零 |
| 找不到时怎样表示 | 交出 `None` |
| 调用有没有影响 | 查询只读，补货决定由检查器计算 |

若让检查器直接读库存对象的内部字典，字典字段一改，检查器就得跟着改。经由 `quantity()` 交接时，双方只依赖数量和缺失值的含义。库存对象也可以由多个检查器共享，每个检查器保留自己的补货阈值。

### 构造时提供需要的对象

下面用很小的数据演示同一个控制器怎样换用不同的计数对象。两个控制器由调用处分别构造，所以可以验证不同初始状态。以后同一个计数器也可以用于其他任务。

```python
class Meter:
    def __init__(self, total):
        self.total = total

    def read(self):
        return self.total


class ThresholdAlert:
    def __init__(self, meter, threshold):
        self._meter = meter
        self._threshold = threshold

    def exceeded(self):
        return self._meter.read() >= self._threshold


normal = ThresholdAlert(Meter(3), 5)
at_boundary = ThresholdAlert(Meter(5), 5)
print("低于阈值", normal.exceeded())
print("刚好到阈值", at_boundary.exceeded())
```

可以沿着“控制器调用计数器”画出依赖方向。计数器不需要知道谁在读取它。把所需对象在构造时传入，读代码的人就能找到它的来源，测试也能准备特定状态。

## 6.3 用类型标注和记录对象传递信息

### 读懂接口上的类型标注

| 标注 | 表达的约定 | 使用位置 |
| --- | --- | --- |
| `code: str` | 参数应为字符串 | 根据编号查找 |
| `dict[str, int]` | 字典的键是字符串，值是整数 | 记录各项库存 |
| `int \| None` | 结果是整数或缺失值 | 查找可能没有结果 |
| `-> str` | 函数交出字符串 | 生成一条检查结论 |
| `-> None` | 函数没有需要调用者使用的返回值 | 更新状态或发送输出 |

类型标注帮助读代码的人、编辑器和静态检查工具理解接口。普通调用不会因为写了标注就自动检查或转换实参。诸如整数必须非负、字符串必须非空，仍要通过校验和文档表达。[Python 官方文档的类型标注](https://docs.python.org/3.12/library/typing.html)

### 标注描述类型，行为还要另外约定

`list[str]` 表示列表中的每项应为字符串。`tuple[str, ...]` 表示长度可变的字符串元组。`A | B` 表示对象可以属于两种类型之一，常用于表示找到对象或交回 `None`。如果还要说明状态只能取几个指定文字，可以在文档里列出允许的值，也可以用 `typing.Literal` 表达给类型检查工具。

```python
from typing import Literal

StockState = Literal["缺失", "用完", "可用"]

def describe(count: int | None) -> StockState:
    if count is None:
        return "缺失"
    if count == 0:
        return "用完"
    return "可用"


print(describe(None))
print(describe(0))
print(describe(2))
```

标注让调用者知道返回值属于一组预定的文字。三个结果的实际含义仍由函数体决定。这里假定现有数量是非负数。若外部可能提供负值，入口还需检查这个约定。

### 把相关参数组成一条记录

一组字段经常一起传递时，可以定义记录类。`dataclasses.dataclass` 根据字段生成初始化、相等比较和便于查看的表示等方法。`frozen=True` 限制常规的字段重新赋值。例中的字段本身都是不可变对象，构造后可在不同组件间传递。

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Measurement:
    station: str
    value: float


def display(measurement: Measurement) -> str:
    return f"{measurement.station} {measurement.value:.1f} ℃"


reading = Measurement(station="东站", value=21.5)
print(display(reading))
print(reading == Measurement("东站", 21.5))
```

两个 `Measurement` 实例的字段值相同，生成的相等比较返回 `True`。如果字段是列表等可变对象，`frozen=True` 仍允许该列表的内容通过引用被修改。[Python 官方文档的 dataclasses](https://docs.python.org/3.12/library/dataclasses.html)

### 可变字段需要分别初始化

记录类还可以维护可变字段。使用 `field(default_factory=list)` 可以让每个实例在没有收到列表时取得一份新列表，和第 5 章在 `__init__` 中分别建立状态的原理相同。

```python
from dataclasses import dataclass, field


@dataclass
class Draft:
    title: str
    notes: list[str] = field(default_factory=list)


first = Draft("上午记录")
second = Draft("下午记录")
first.notes.append("核对温度")
print(first)
print(second)
```

`default_factory` 接收可调用对象 `list`，创建实例时再调用它。若每个实例要保留不同的修改历史，使用工厂可以让这种独立性在定义中直接表达。

## 6.4 模块、导入与入口

### 导入能力并管理名字

通常一个 `.py` 文件可以作为模块。每个模块有自己的名字空间，导入可将其中的能力引入当前模块。`import math` 引入模块名，调用时写 `math.sqrt(9)`。`from statistics import mean` 直接引入指定的函数名。

```python
import math
from statistics import mean

print(math.sqrt(9))
print(mean([18, 21, 24]))
```

模块首次导入时会执行顶层语句。把演示或交互步骤放在 `main()`，再用 `if __name__ == "__main__":` 判断是否启动入口。这样其他模块可以导入其中定义的对象，入口代码在模块作为程序执行时才运行。

### 每种导入写法在当前模块建立什么名字

| 写法 | 本模块可用的名字 | 典型用法 |
| --- | --- | --- |
| `import statistics` | `statistics` | 用模块名标明能力的来源 |
| `import statistics as stats` | `stats` | 使用更短且明确的模块别名 |
| `from statistics import mean` | `mean` | 直接使用模块中的某个对象 |
| `from .readings import Measurement` | `Measurement` | 在包内从同包模块导入记录类 |

```python
import statistics
import statistics as stats
from math import sqrt as root

print("两处引用同一个模块", statistics is stats)
print("模块名", stats.__name__)
print("计算均值和平方根", stats.mean([3, 6, 9]), root(16))
```

普通的重复导入会使用已加载的模块对象。若模块顶层立刻运行大量工作，第一次导入时就会触发这些行为。把构造、读文件或显示结果放进入口函数，可以先只导入定义来测试。

### 使用入口判断区分两种运行方式

```python
def make_message(label):
    return f"准备处理 {label}"


def main():
    print(make_message("测量表"))


if __name__ == "__main__":
    main()
```

在网页示例中代码作为入口执行，`__name__` 为 `"__main__"`，于是调用 `main()`。如果这段定义位于 `report.py`，另一个模块导入 `report` 时，`__name__` 是模块名。调用者取得 `report.make_message` 后可以自己决定何时使用它。

## 6.5 用包和依赖方向组织程序

### 按职责划分模块

相关模块可以组成包。普通包包含 `__init__.py`，其中可以安排包的初始化或对外入口。包内可以用 `from .readings import Measurement` 导入同包的模块，也可以使用从包名开始的绝对导入。示意目录中的 `report.py` 需要了解记录的格式，记录类则可以独立存在。

```text
weather/
    __init__.py    普通包的初始化文件
    readings.py    定义 Measurement
    report.py      导入 Measurement，组织报告
    __main__.py    构造数据并调用报告功能
```

从包含 `weather` 的目录启动包时，`python -m weather` 会执行 `weather/__main__.py`。当两个模块出现相互导入时，可以沿着职责检查哪一方真正需要另一方的能力，或把共同使用的记录类型放在双方都能导入的位置。[Python 官方教程的模块与包](https://docs.python.org/3.12/tutorial/modules.html)

### 从实际调用推导模块之间的关系

给出一个目录结构后，还要解释每个文件需要谁。下面的报告程序从入口取得示例数据，由报告模块组织输出。记录模块只负责表达数据，可以独立导入。

```text
weather/__main__.py
    导入 readings 里的 Measurement。
    导入 report 里的 summarize。
    构造读数，再交给 summarize。

weather/report.py
    使用 from .readings import Measurement。
    接收读数，交回摘要文字。

weather/readings.py
    定义 Measurement 的字段和含义。
```

从文件的依赖来看，`report` 需要认识 `Measurement`，而 `readings` 无需导入 `report`。如果发现两边互相导入，可以先检查其中一个模块是否包办了两项职责。若双方只共享一个记录类型，把记录放在独立模块中，两个模块都可以沿同一方向导入它。

### 在模块边界保留可以测试的能力

模块的职责和对象的职责是不同层面。一个模块可以包含几个紧密配合的类和函数。先把接口设计清楚，再按照变化原因划分文件。例如调整摘要格式时，主要修改报告模块。增加一种读数来源时，可以在入口换用另一组对象。只要摘要收到的记录仍符合约定，已有的摘要测试仍可复用。

## 6.6 回到案例 组织多活动报名

| 角色 | 提供的能力 | 被谁使用 |
| --- | --- | --- |
| `Request` | 用两个字段记录活动编号与学号 | 入口和报名服务 |
| `Activity` | 按自己的规则登记，交出名单快照 | 报名服务和查询者 |
| `ActivityCatalog` | 按编号找到活动，缺失时交出 `None` | 报名服务 |
| `EnrollmentService` | 取得活动对象后请求登记，返回回执 | 入口和测试 |
| `main` | 构造对象、提交请求和呈现结果 | 程序入口 |

先假设目录会按编号交出活动对象。服务用查找的结果决定下一步，找到时调用活动的方法，未找到时返回相应回执。用字典实现目录后，服务可以直接使用这份实现。

```text
任务：受理多场活动的报名
    1. 输入：一条包含活动编号和学号的请求。
    2. 处理：用编号向目录查找活动。
        2.1 找到活动时，把学号交给该对象办理登记。
        2.2 查不到时，生成“活动不存在”的回执。
    3. 输出：交回回执，由入口呈现。
```

下面把各部分放在一起，便于对照接口和调用顺序。

```python multi-activity-reference solution
from dataclasses import dataclass


@dataclass(frozen=True)
class Request:
    activity_id: str
    student_id: str


class Activity:
    def __init__(self, title: str, capacity: int):
        if type(capacity) is not int or capacity < 0:
            raise ValueError("容量须为非负整数")
        self.title = title
        self._capacity = capacity
        self._roster: dict[str, str] = {}

    def register(self, raw_id: str) -> str:
        student_id = raw_id.strip()
        if not student_id:
            return "空学号"
        if student_id in self._roster:
            return "重复"
        if len(self._roster) >= self._capacity:
            return "满员"
        self._roster[student_id] = "已报名"
        return "通过"

    def student_ids(self) -> tuple[str, ...]:
        return tuple(self._roster)

    def __len__(self) -> int:
        return len(self._roster)


class ActivityCatalog:
    def __init__(self, activities: dict[str, Activity]):
        self._activities = dict(activities)

    def find(self, activity_id: str) -> Activity | None:
        return self._activities.get(activity_id)


class EnrollmentService:
    def __init__(self, catalog: ActivityCatalog):
        self._catalog = catalog

    def submit(self, request: Request) -> str:
        activity = self._catalog.find(request.activity_id)
        if activity is None:
            return "活动不存在"
        return activity.register(request.student_id)


def main() -> None:
    museum = Activity("博物馆", 2)
    lab = Activity("实验室", 1)
    catalog = ActivityCatalog({"museum": museum, "lab": lab})
    service = EnrollmentService(catalog)

    requests = [
        Request("museum", "S01"),
        Request("lab", "S01"),
        Request("lab", "S02"),
        Request("unknown", "S03"),
        Request("lab", "S01"),
    ]
    for request in requests:
        print(request.activity_id, request.student_id, service.submit(request))
    print(museum.title, museum.student_ids())
    print(lab.title, lab.student_ids())


if __name__ == "__main__":
    main()
```

回执依次是“通过、通过、满员、活动不存在、重复”。两场活动最终都只有 `S01`。目录复制了编号到活动的映射，映射里的值仍引用原来的活动实例，所以入口可以用 `museum.student_ids()` 看到服务完成的登记。服务用 `is None` 检查查找是否失败，长度为零的活动也会接收到它的第一条请求。

程序增长后，可以把 `Activity` 放在 `activity.py`，把目录放在 `catalog.py`，把请求和服务放在 `service.py`，把构造与显示放在 `__main__.py`。入口导入前三者，服务导入目录，目录导入活动。沿这条方向，活动类始终可以独立用于另一个程序。

### 跟踪请求并验证职责边界

| 请求 | 目录交出的结果 | 服务交出的回执 | 哪个活动会改变 |
| --- | --- | --- | --- |
| museum / S01 | 空的博物馆活动 | 通过 | 博物馆 |
| lab / S01 | 空的实验室活动 | 通过 | 实验室 |
| lab / S02 | 已满的实验室活动 | 满员 | 无 |
| unknown / S03 | `None` | 活动不存在 | 无 |
| lab / S01 | 已满的实验室活动 | 重复 | 无 |

这个例子里，查到一个长度为零的活动是正常结果。判断 `activity is None` 可以让空活动收到第一条请求。如果改用 `if not activity`，活动长度为零时也会进入“活动不存在”的分支，可以试着改动这一行并观察结果。

| `activity.py` | `Activity` | 活动规则在本模块内处理 |
| `catalog.py` | `ActivityCatalog` | `from .activity import Activity` |
| `service.py` | `Request`、`EnrollmentService` | `dataclass` 和同包的 `ActivityCatalog` |
| `__main__.py` | `main` 和入口调用 | 从前三个模块取得类，构造并连接它们 |

单文件示例可以先验证角色之间的约定。把类按上表分开时，类内的业务判断可以保持原样，入口仍用同一批请求核对回执和名单。第 7 章会把这些预期写进可重复执行的测试。[第 7 章 对象协作的可靠性](07.md)

完成多文件练习后，试着把 `is None` 改为 `not activity`。看第一次请求为什么进不了活动，再恢复判断。第 7 章会用一个更小的例子练习写出这样的检查。[进入失败用例练习](07.md#registration-regression)

## 练习

- 把 `main` 中的目录换成只包含 `lab` 的目录，保留原请求。预测前两条回执和两场活动的名单。
- 将 `activity is None` 改成 `not activity`，观察最初的空活动能否接受第一条请求，再恢复原判断。
- 为 `Draft` 创建第三个实例，给它增加一条备注。预测另外两个实例的备注。
- 如果要把回执改成另一种显示格式，指出应改动哪个角色。若要按另一套编号查找活动，再指出应改动哪个角色。

:::answer
第一条回执变为“活动不存在”。第二条仍然“通过”。博物馆实例仍存在，目录无法按 museum 找到它，因此名单为空。实验室的名单为 ("S01",)。
`not activity` 会把长度为零的活动判为假。首次登记无法发生，两场活动都保持为空。
第三个 Draft 用工厂取得新列表。第一份仍有“核对温度”，第二份仍为空。
显示格式由入口或专门的显示组件处理。查找规则由目录处理，服务仍通过 find 取得活动。
:::
