# 多对象协作与程序组织
> 组织活动查询与报名服务，用接口、类型标注和模块说明各角色怎样协作。

## 6.1 收到活动编号后，谁负责找到对象

第 5 章可以直接拿着 `museum` 或 `lab` 对象办理报名。真正收到的请求通常只有活动编号和学号，例如 `("museum", "S01")`。程序要先把编号对应到活动，再请该活动决定是否接受请求。

- 输入是若干已开放的活动，以及包含活动编号和学号的报名请求。
- 找到活动时，沿用活动自己的空学号、重复和容量规则。找不到活动时，返回“活动不存在”。
- 输出是每次请求的回执。查询未知编号后，已有活动的名单应保持原样。

从接收请求到给出回执，中间有查找、更新状态和呈现结果几项工作。把这些工作分给不同角色，才能独立调整查询方式或展示方式。

## 6.2 组合对象与约定接口

当一个对象持有另一个对象并通过其公开操作完成一部分工作，就形成了对象组合。例如，一个补货检查器接收库存查询对象。它只需知道查询操作的名字、需要提供的参数、会交出的结果。创建检查器时把所需对象传进去，就可以让调用者选择它使用哪一份库存数据。

```python
class Stock:
    def __init__(self, quantities: dict[str, int]):
        self._quantities = dict(quantities)

    def quantity(self, code: str) -> int | None:
        return self._quantities.get(code)


class ReorderCheck:
    def __init__(self, stock: Stock, minimum: int):
        self._stock = stock
        self._minimum = minimum

    def check(self, code: str) -> str:
        quantity = self._stock.quantity(code)
        if quantity is None:
            return "无此货品"
        if quantity < self._minimum:
            return "需要补货"
        return "库存足够"


check = ReorderCheck(Stock({"P1": 0, "P2": 8}), minimum=3)
for code in ["P1", "P2", "P3"]:
    print(code, check.check(code))
```

`quantity` 的接口约定是接收货品编号，返回非负整数，找不到时返回 `None`。检查器拿到 0 时会继续判断是否补货，拿到 `None` 时直接返回“无此货品”。使用接口时，除了记住方法名，还要明确如何解释返回值、调用是否改变状态、什么情况需要报告失败。

依赖方向可以沿着调用关系看出。检查器请求库存对象提供数量，库存对象可以独立使用。测试时可以构造一份只有一两项的库存，覆盖零库存、正常库存和未知编号。

## 6.3 用类型标注和记录对象传递信息

### 读懂接口上的类型标注

| 标注 | 表达的约定 | 使用位置 |
| --- | --- | --- |
| `code: str` | 参数应为字符串 | 根据编号查找 |
| `dict[str, int]` | 字典的键是字符串，值是整数 | 记录各项库存 |
| `int \| None` | 结果是整数或缺失值 | 查找可能没有结果 |
| `-> str` | 函数交出字符串 | 生成一条检查结论 |
| `-> None` | 函数没有需要调用者使用的返回值 | 更新状态或发送输出 |

类型标注帮助读代码的人、编辑器和静态检查工具理解接口。普通调用不会因为写了标注就自动检查或转换实参。诸如整数必须非负、字符串必须非空，仍要通过校验和文档表达。[Python 官方文档的类型标注](https://docs.python.org/3.12/library/typing.html)

### 把相关参数组成一条记录

一组字段经常一起传递时，可以定义记录类。`dataclasses.dataclass` 根据字段生成初始化、相等比较和便于查看的表示等方法。`frozen=True` 限制常规的字段重新赋值。例中的字段本身都是不可变对象，构造后可在不同组件间传递。

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Measurement:
    station: str
    value: float


def display(measurement: Measurement) -> str:
    return f"{measurement.station} {measurement.value:.1f} ℃"


reading = Measurement(station="东站", value=21.5)
print(display(reading))
print(reading == Measurement("东站", 21.5))
```

两个 `Measurement` 实例的字段值相同，生成的相等比较返回 `True`。如果字段是列表等可变对象，`frozen=True` 仍允许该列表的内容通过引用被修改。[Python 官方文档的 dataclasses](https://docs.python.org/3.12/library/dataclasses.html)

## 6.4 从一个文件到模块与包

### 导入能力并管理名字

通常一个 `.py` 文件可以作为模块。每个模块有自己的名字空间，导入可将其中的能力引入当前模块。`import math` 引入模块名，调用时写 `math.sqrt(9)`。`from statistics import mean` 直接引入指定的函数名。

```python
import math
from statistics import mean

print(math.sqrt(9))
print(mean([18, 21, 24]))
```

模块首次导入时会执行顶层语句。把演示或交互步骤放在 `main()`，再用 `if __name__ == "__main__":` 判断是否启动入口。这样其他模块可以导入其中定义的对象，入口代码在模块作为程序执行时才运行。

### 按职责划分模块

相关模块可以组成包。普通包包含 `__init__.py`，其中可以安排包的初始化或对外入口。包内可以用 `from .readings import Measurement` 导入同包的模块，也可以使用从包名开始的绝对导入。示意目录中的 `report.py` 需要了解记录的格式，记录类则可以独立存在。

```text
weather/
    __init__.py    普通包的初始化文件
    readings.py    定义 Measurement
    report.py      导入 Measurement，组织报告
    __main__.py    构造数据并调用报告功能
```

从包含 `weather` 的目录启动包时，`python -m weather` 会执行 `weather/__main__.py`。当两个模块出现相互导入时，可以沿着职责检查哪一方真正需要另一方的能力，或把共同使用的记录类型放在双方都能导入的位置。[Python 官方教程的模块与包](https://docs.python.org/3.12/tutorial/modules.html)

## 6.5 回到案例 组织多活动报名

| 角色 | 提供的能力 | 被谁使用 |
| --- | --- | --- |
| `Request` | 用两个字段记录活动编号与学号 | 入口和报名服务 |
| `Activity` | 按自己的规则登记，交出名单快照 | 报名服务和查询者 |
| `ActivityCatalog` | 按编号找到活动，缺失时交出 `None` | 报名服务 |
| `EnrollmentService` | 取得活动对象后请求登记，返回回执 | 入口和测试 |
| `main` | 构造对象、提交请求和呈现结果 | 程序入口 |

先假设目录会按编号交出活动对象。服务用查找的结果决定下一步，找到时调用活动的方法，未找到时返回相应回执。用字典实现目录后，服务可以直接使用这份实现。以下程序把各部分放在同一个示例中，便于在网页运行。

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Request:
    activity_id: str
    student_id: str


class Activity:
    def __init__(self, title: str, capacity: int):
        if type(capacity) is not int or capacity < 0:
            raise ValueError("容量须为非负整数")
        self.title = title
        self._capacity = capacity
        self._roster: dict[str, str] = {}

    def register(self, raw_id: str) -> str:
        student_id = raw_id.strip()
        if not student_id:
            return "空学号"
        if student_id in self._roster:
            return "重复"
        if len(self._roster) >= self._capacity:
            return "满员"
        self._roster[student_id] = "已报名"
        return "通过"

    def student_ids(self) -> tuple[str, ...]:
        return tuple(self._roster)

    def __len__(self) -> int:
        return len(self._roster)


class ActivityCatalog:
    def __init__(self, activities: dict[str, Activity]):
        self._activities = dict(activities)

    def find(self, activity_id: str) -> Activity | None:
        return self._activities.get(activity_id)


class EnrollmentService:
    def __init__(self, catalog: ActivityCatalog):
        self._catalog = catalog

    def submit(self, request: Request) -> str:
        activity = self._catalog.find(request.activity_id)
        if activity is None:
            return "活动不存在"
        return activity.register(request.student_id)


def main() -> None:
    museum = Activity("博物馆", 2)
    lab = Activity("实验室", 1)
    catalog = ActivityCatalog({"museum": museum, "lab": lab})
    service = EnrollmentService(catalog)

    requests = [
        Request("museum", "S01"),
        Request("lab", "S01"),
        Request("lab", "S02"),
        Request("unknown", "S03"),
        Request("lab", "S01"),
    ]
    for request in requests:
        print(request.activity_id, request.student_id, service.submit(request))
    print(museum.title, museum.student_ids())
    print(lab.title, lab.student_ids())


if __name__ == "__main__":
    main()
```

回执依次是“通过、通过、满员、活动不存在、重复”。两场活动最终都只有 `S01`。目录复制了编号到活动的映射，映射里的值仍引用原来的活动实例，所以入口可以用 `museum.student_ids()` 看到服务完成的登记。服务用 `is None` 检查查找是否失败，长度为零的活动也会接收到它的第一条请求。

程序增长后，可以把 `Activity` 放在 `activity.py`，把目录放在 `catalog.py`，把请求和服务放在 `service.py`，把构造与显示放在 `__main__.py`。入口导入前三者，服务导入目录，目录导入活动。沿这条方向，活动类始终可以独立用于另一个程序。
