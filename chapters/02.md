# 容器对象与数据组织
> 从管理报名名单出发，比较列表、元组、字典和集合，再检验共享引用和复制怎样影响数据修改。

## 2.1 报名任务从一个人数扩展到多条记录

第 1 章能算出活动还剩几个名额。到了签到现场，组织者还需要按学号查找报名记录，并判断哪些人还没到。

先用三条报名记录明确任务。S01、S02 和 S03 都已报名，签到顺序是 S02、S01、S02。查询 S02 时要能取得姓名，原始签到记录要保留 S02 的两次签到，未签到名单则只应包含 S03。

活动配置也需要组织起来。名称、容量、出发地和目的地要能一起查阅。调整容量或更新报名记录前，有时还要保存一份旧数据，以便事后核对。

这项任务涉及三种数据关系。签到记录依赖先后顺序，报名名单需要按学号查找，签到状态取决于某个学号是否出现。要保留修改前的记录，还需要确定复制哪一层数据。

## 2.2 按数据关系选择容器

容器把多个对象组织起来。选择容器之前，先问以后要按位置取得元素、按键查找值，还是只判断某个元素是否存在。

| 类型 | 组织和查找方式 | 能否原地修改 | 典型用途 |
| --- | --- | --- | --- |
| 列表 `list` | 保留顺序，按位置取元素，允许重复 | 可以 | 会增删或调整顺序的一组数据 |
| 元组 `tuple` | 保留顺序，按位置取元素，允许重复 | 各位置的引用固定 | 固定的一组值，例如一对坐标 |
| 字典 `dict` | 把唯一的键关联到值，按键查找 | 可以 | 由编号或名称查找对应的数据 |
| 集合 `set` | 元素唯一，支持成员判断和集合运算 | 可以 | 去重、检查成员和比较两组数据 |

四种容器都可以用 `len()` 查看有多少项，也可以用 `in` 检查成员。对字典来说，`in` 检查的是键，`len()` 统计的是键值对。列表和元组用下标取元素，字典用方括号时填入的是键，即使这个键恰好是整数。

## 2.3 列表和元组 按位置组织数据

### 列表可以增删和调整

用方括号写列表。下标从 0 开始，`numbers[0]` 取得第一项，`numbers[-1]` 取得最后一项。切片 `numbers[1:3]` 取得下标 1 和 2 的元素，右边界 3 不包含在内。单个下标超出范围会引发 `IndexError`，切片的边界会按序列实际长度截取。

可以给某个位置重新赋值。`append()` 把传入的对象作为一项加到末尾，`extend()` 则把传入的一组元素逐项加入。用 `pop()` 可以取出并删除一项，省略位置时取最后一项。`remove()` 删除第一个等于指定值的元素。

```python
numbers = [30, 10, 20, 10]

print("首项和末项", numbers[0], numbers[-1])
print("切片", numbers[1:3])

numbers[0] = 25
numbers.append(40)
numbers.extend([50, 60])
print("排序结果", sorted(numbers))
print("当前列表", numbers)
```

列表中的两个 10 都会保留。`sorted(numbers)` 返回一个排好序的新列表，`numbers` 仍保留原来的顺序。要直接改变列表的排列，可以调用 `numbers.sort()`。这类只修改容器的方法通常返回 `None`，用原来的名字继续读取结果。[Python 列表方法](https://docs.python.org/3.12/tutorial/datastructures.html#more-on-lists)

### 元组适合把几项值作为一组

例如，可以用 `(3, 4)` 表示一个平面坐标。元组支持读取、切片和解包。解包时，左边的名字分别绑定到对应位置的元素。对于下面这种逐项解包，名字的数量要与元素数量一致。

```python
point = (3, 4)
x, y = point

print("坐标", x, y)
print("第二项", point[1])
print("单元素元组", (3,))
print("去掉逗号后的类型", type((3)))
```

一个元素的元组需要逗号，例如 `(3,)`。元组各位置的引用在创建后固定，适合表达结构已确定的一组信息。列表和元组之间可以用 `list()` 和 `tuple()` 转换。

## 2.4 字典 按键组织数据

字典保存键和值的对应关系。表达式 `labels["ok"]` 按键取得值。同一个键只能关联一个当前值。再次给该键赋值，就会更新它的值。

读取缺失的键会引发 `KeyError`。可以先用 `in` 检查键是否存在，或者用 `get()` 为缺失的键提供一个默认值。字典还提供 `keys()`、`values()` 和 `items()`，分别返回键、值和键值对的视图。视图会反映字典的当前内容。要保留某一时刻有哪些键，可以把键视图转成列表。

```python
labels = {"ok": "正常", "warn": "警告"}

print(labels["ok"])
print(labels.get("error", "未知状态"))

key_view = labels.keys()
saved_keys = list(key_view)
labels["warn"] = "注意"
labels["error"] = "错误"

print("存在 error 键", "error" in labels)
print("视图中的当前键", list(key_view))
print("之前保存的键", saved_keys)
print("键值对", list(labels.items()))
```

字典按键的插入顺序提供数据。更新 `warn` 的值后，这个键仍在原来的位置。新增 `error` 后，键视图里能看到它，之前保存的键列表仍只有 `ok` 和 `warn`。需要删除键时，可以用 `del labels["warn"]`，或用 `pop()` 删除并取得原来的值。

键需要可哈希，也就是散列值在对象存续期间保持稳定，彼此相等的对象具有相同的散列值。整数、字符串和只包含可哈希成员的元组都可以作为键。列表、字典和集合属于不可哈希的内置类型。值可以引用任意对象，包括另一个字典。[Python 字典类型](https://docs.python.org/3.12/library/stdtypes.html#mapping-types-dict)

## 2.5 集合 按成员和集合关系组织数据

集合保存互不重复的元素，元素也需要可哈希。用 `set()` 创建空集合，`{}` 创建的是空字典。把列表交给 `set()` 可以合并重复值。可以用 `add()` 加入成员，用 `discard()` 移除成员，成员已经缺失时也能继续执行。

集合可以直接求两组数据的关系。`&` 求交集，`|` 求并集，`-` 求左边有而右边没有的元素，`^` 求只出现在其中一边的元素。

```python
left = {"A", "B", "C"}
right = {"B", "C", "D"}

print("交集", sorted(left & right))
print("并集", sorted(left | right))
print("左边独有", sorted(left - right))
print("只出现在一边", sorted(left ^ right))
print("去重结果", sorted(set(["A", "A", "B"])))
```

集合按成员查找。元素可以比较大小时，可以用 `sorted()` 得到按顺序排列的列表。用 `left <= right` 可以判断左边的每个成员是否都在右边。

## 2.6 共享引用、可变性与复制

第 1 章的名字绑定规则也适用于容器。执行 `alias = original`，两个名字便指向同一个对象。列表、字典和集合可以原地修改，因此通过其中一个名字改动容器，另一个名字也会看到变化。

需要保留原来的数据时，可以选择复制的范围。浅复制新建外层容器，里面的引用仍指向原来的元素。深复制会进一步复制嵌套的可变成员，例如这里的内层字典。Python 标准库提供 `deepcopy()`，下面先用 `from` 和 `import` 取用它。

```python
from copy import deepcopy

original = [{"value": 1}]
alias = original
shallow = original.copy()
deep = deepcopy(original)

original.append({"value": 2})
original[0]["value"] = 9

print("外层长度", len(alias), len(shallow), len(deep))
print("第一项的值", alias[0]["value"], shallow[0]["value"], deep[0]["value"])
print("共享第一项", shallow[0] is original[0], deep[0] is original[0])
```

第一行得到 2、1、1。追加动作改的是原列表，浅复制与深复制都有自己的外层列表。第二行得到 9、9、1。改第一项的值是在修改内层字典，原列表和浅复制共享这个字典，深复制有单独的一份。第三行用 `is` 验证内层引用的关系。[Python 浅复制与深复制](https://docs.python.org/3.12/library/copy.html)

元组固定的是各位置的引用。如果元组中的某一项是列表，仍可以找到这个列表并修改它的内容。

```python
record = ("数值", [1, 2])
record[1].append(3)
print(record)
```

选择复制方法时，可以先指出准备改哪一层。只需要增删外层的项时，可以浅复制。如果旧记录还要保留内层的修改前状态，就要把相关的可变成员也复制下来。

## 2.7 组织活动配置和报名名单

### 让每种容器承担相应的工作

回到签到任务。用字典保存活动配置和报名名单，分别按配置名称和学号查找。出发地与目的地是固定顺序的一对值，用元组保存。签到先后顺序用列表保留，签到过的学号用集合去重。用已报名的学号集合减去已签到的学号集合，就能查出还没签到的人。

```python
activity = {
    "name": "博物馆参观",
    "capacity": 30,
    "route": ("教学楼", "博物馆"),
}
registrations = {
    "S01": {"name": "林同学", "group": "一班"},
    "S02": {"name": "周同学", "group": "二班"},
    "S03": {"name": "吴同学", "group": "一班"},
}
arrival_order = ["S02", "S01", "S02"]
checked_in = set(arrival_order)
missing = set(registrations) - checked_in

print("活动", activity["name"])
print("目的地", activity["route"][1])
print("剩余名额", activity["capacity"] - len(registrations))
print("S02 姓名", registrations["S02"]["name"])
print("原始签到记录", arrival_order)
print("未签到学号", sorted(missing))
```

目前有 3 人报名，剩余 27 个名额。签到列表保留了 S02 的两次记录。计算未签到名单时，只用去重后的学号，得到 S03。向字典写入已存在的学号会替换记录。第 3 章会先检查学号是否重复，再决定是否写入。

### 验证修改会影响哪些数据

下面先保存旧配置，再增加一条报名记录并修改已有记录的班级。运行前可以预测，哪种副本会看到新增的学号，哪种副本会看到班级变化。

```python
from copy import deepcopy

activity = {"capacity": 30, "route": ("教学楼", "博物馆")}
old_config = activity.copy()
activity["capacity"] = 32
print("当前容量和原容量", activity["capacity"], old_config["capacity"])

registrations = {"S01": {"name": "林同学", "group": "一班"}}
shared = registrations
shallow = registrations.copy()
saved = deepcopy(registrations)

registrations["S02"] = {"name": "周同学", "group": "二班"}
registrations["S01"]["group"] = "二班"

print("共享、浅复制、深复制的人数", len(shared), len(shallow), len(saved))
print("S01 的班级", shared["S01"]["group"], shallow["S01"]["group"], saved["S01"]["group"])
```

容量从 30 改为 32，旧配置仍显示 30，因为修改的是活动字典外层的键值关系。名单的两次修改则分别作用于外层和内层。

| 核对结果 | 共享引用 `shared` | 浅复制 `shallow` | 深复制 `saved` |
| --- | --- | --- | --- |
| 新增 S02 后的人数 | 2 | 1 | 1 |
| 修改 S01 后看到的班级 | 二班 | 二班 | 一班 |

新增学号改的是外层字典，修改班级改的是该学号对应的内层字典。先找出哪一层被修改，再检查各处是否引用同一个对象，就能解释表里的结果。
