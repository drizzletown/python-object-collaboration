# 对象协作的流程控制
> 用条件和循环安排协作步骤，按顺序处理报名请求并解释每一条回执。

## 3.1 一批报名请求怎样逐条处理

第 2 章已经选好保存活动配置和名单的容器。现在活动开放报名，程序收到一批有先后顺序的学号。组织者需要为每条请求给出回执，也需要知道整批处理完后谁进入了名单。

- 输入是一场容量为 2 的活动、一份空名单，以及依次到达的请求 `S01`、空白、`S02`、`S03`、`S01`。
- 处理时先去掉学号首尾空白，再依次检查空学号、重复、满员。满足登记条件时才更新名单。
- 输出应有五条回执。最后一次请求到达时，名单既已满又包含 `S01`，按本活动的规则应回执“重复”。

如果只有一条请求，仍要根据名单和容量选择回执。如果有一批请求，同一判断要反复执行，而且每次判断都要使用上一条处理后的名单。这两类要求决定了程序既要能选择路径，也要能组织重复。

## 3.2 用条件选择执行路径

### 条件的真值与代码块

`if` 后面的条件可以是比较结果，也可以直接是对象。空字符串、空容器、数值零、`None` 和 `False` 的真值都为假。例如，`if not text` 对空字符串成立。冒号后缩进的语句属于这个分支，退回原来的缩进就离开分支。教材统一用四个空格表示一级缩进。

### 独立判断与互斥分支

| 写法 | 执行规则 | 适合的任务 |
| --- | --- | --- |
| 单个 `if` | 条件成立时执行该块 | 需要时追加一条提示 |
| 多个并列的 `if` | 各自判断，多个条件可以同时成立 | 分别检查多项指标 |
| `if / elif / else` | 从上往下检查，只执行首个成立的分支。前面都不成立时执行可选的 `else` | 按阈值选择一个级别 |
| 嵌套的 `if` | 外层分支执行后才检查内层条件 | 先确认有数据，再检查取值 |

下面给温度划分级别。35 同时满足两个阈值，所以要把更高的阈值放在前面。最后两个 `if` 分别检查温度和湿度，可以同时打印两条建议。

```python
temperature = 35
humidity = 80

if temperature >= 35:
    level = "高温"
elif temperature >= 30:
    level = "偏热"
else:
    level = "常温"
print(level)

if temperature >= 30:
    print("注意通风")
if humidity >= 75:
    print("注意防潮")
```

若只需根据条件在两个值中选一个，可以写 `label = "合格" if score >= 60 else "待复核"`。每条路径需要执行多条语句时，使用分支代码块来展示步骤。

### 先判断能否执行，再判断要怎样执行

同一个对象的不同状态可能需要不同的处理。温度记录尚未收到时，可以先提示缺失。有了读数后，再检查阈值。空值判断必须放在大小比较前，避免拿缺失值参与数值运算。

```python
reading = None
limit = 28

if reading is None:
    message = "等待读数"
elif reading >= limit:
    message = "达到阈值"
else:
    message = "低于阈值"

print(message)
```

把 `reading` 依次改为 `0`、`27`、`28`。零和 27 都有读数，只是低于阈值。等于 28 时恰好满足 `>=`。如果只需要判断“是否有读数且达到阈值”，也可以写 `reading is not None and reading >= limit`，利用短路先检查安全条件。

### 用一张表检查边界和重叠

| 输入情形 | 首个成立的条件 | 执行结果 |
| --- | --- | --- |
| 尚未取得读数 | `reading is None` | 等待读数 |
| 27，低于阈值 | 前两个条件都不成立 | 低于阈值 |
| 28，正好等于阈值 | `reading >= limit` | 达到阈值 |
| 35，高于阈值 | `reading >= limit` | 达到阈值 |

设计分支时，可以分别挑选一个能进入每条分支的输入。两个条件都能成立时，再检查它们的先后是否符合任务规则。测试分界点时，要特意包含恰好等于阈值的情况。

## 3.3 用 for 遍历一组对象

### 用 for 逐项处理可迭代对象

`for` 从可迭代对象中逐项取得值，每一轮把当前值绑定到循环变量。列表、元组、字符串、字典和集合都可以遍历。遍历字典时默认得到键，用 `items()` 可以同时取得键和值。空容器不会执行循环体。

| 工具 | 依次提供什么 | 使用场景 |
| --- | --- | --- |
| `range(start, stop, step)` | 从起点按步长取整数，不包含终点 | 重复固定次数或按间隔取数 |
| `enumerate(values, start=1)` | 序号与当前值组成的二元组 | 给记录编号 |
| `zip(left, right)` | 从两组数据各取一项组成二元组 | 把名称与测量值配对 |
| `mapping.items()` | 键和值组成的二元组 | 同时读取字典的两个字段 |

```python
for minute in range(0, 10, 3):
    print("采样时间", minute)

stations = ["东站", "西站"]
readings = [18, 21]
for row, (station, reading) in enumerate(zip(stations, readings), start=1):
    print(row, station, reading)
```

`range(0, 10, 3)` 给出 0、3、6、9。上例先用 `zip` 配对，再用 `enumerate` 编号。`zip` 默认到最短的一组为止。如果两组数据应当一一对应，可用 `zip(stations, readings, strict=True)`，在遍历发现长度不一致时报告错误。

### 字典、序列和循环变量

遍历字典可以按键、值或键值对进行。循环每取一项就绑定一次循环变量。用 `for name, amount in readings.items()`，元组中的两个位置分别绑定到两个名字。读取字典时，可以准备另一份容器收集结果，待遍历结束再决定怎样更新原数据。

```python
readings = {"东站": 18, "西站": None, "南站": 20}
available = {}

for station, value in readings.items():
    if value is not None:
        available[station] = value
        print(station, value)

print("可用记录", available)
print("原记录", readings)
```

如果在遍历一个字典时增删其键，正在遍历的数据范围会改变，Python 可能报告运行错误。也可以先用 `list(readings)` 取得键的快照，再根据各个键更新字典。这个办法利用了第 2 章的视图和复制知识。

### 嵌套循环描述两层重复

先取一个地点，再对这个地点逐项读取时段。内层循环在每次外层循环时重新开始。缩进表示两个层次分别包含哪些工作。

```python
rooms = ["东室", "西室"]
times = ["上午", "下午"]

for room in rooms:
    print("开始安排", room)
    for time in times:
        print(room, time)
    print("完成安排", room)
```

按顺序读输出。东室的两个时段都处理完才轮到西室。如果把两层循环交换，地点和时段的所有组合仍会出现，先后次序会改为先安排各个地点的上午，再安排下午。

## 3.4 用 while 持续到条件改变

### 用 while 等待条件变化

`while` 在每轮开始前重新判断条件，条件一开始为假时一次也不执行。设计这种循环要指出什么变化会让条件变假，或者在哪个分支明确退出。

```python
balance = 38
payment = 15

while balance >= payment:
    balance -= payment
    print("扣款后的余额", balance)

print("停止扣款，余额", balance)
```

每次扣款都使余额变小，余额从 38 到 23，再到 8，循环结束。这里约定 `payment` 是正数，这个前提保证循环会停止。

### 找出每轮变化的量

还可以用 `while` 重复缩小差距。例如，纸条宽 64 毫米，每次折成一半，直到不超过 10 毫米。每轮之后都重新检查宽度，折叠次数也要一起更新。

```python
width = 64
limit = 10
folds = 0

while width > limit:
    width = width // 2
    folds += 1
    print("第几次、当前宽度", folds, width)

print("总次数", folds)
```

这里依次得到 32、16、8，第三轮后条件为假。若初始宽度已经不超过限制，循环执行零次。写这类循环时，先检查初始化是否给出了第一次判断所需的数据，再检查每条会继续执行的路径是否都推进了状态。

## 3.5 选择跳过、退出或继续查找

### 跳过一轮、提前退出与查找结束

`continue` 跳过本轮剩余的语句，`break` 退出所在的最内层循环。循环后可以接 `else`，在循环正常结束时执行。查找任务中常用 `break` 标记找到目标，用循环的 `else` 处理查找完毕仍未找到的情况。

```python
readings = [None, 16, 20, 28, 31]

for reading in readings:
    if reading is None:
        continue
    if reading >= 25:
        print("首次达到阈值", reading)
        break
else:
    print("没有达到阈值的读数")
```

把 28 和 31 都改为小于 25 的数，再运行一次。循环会检查完所有数据，然后执行 `else`。

### break 只退出所在的循环

在两层循环中，内层的 `break` 结束本次内层搜索，外层仍可以继续处理下一个对象。下面为每一行寻找第一个非空读数。找到了就停止这一行，整行都没有时输出缺失。

```python
rows = [[None, 18, 21], [None], [19, None]]
for number, row in enumerate(rows, start=1):
    for value in row:
        if value is not None:
            print(number, "首个读数", value)
            break
    else:
        print(number, "本行没有读数")
```

`else` 与内层 `for` 对齐，所以它说明“这一行没有找到”。如果在 `while` 里使用 `continue`，要检查跳过后是否仍推进循环。计数或位置的更新若被跳过，下一轮可能一直看到同一条件。

## 3.6 用循环累计、筛选和分组

### 每轮交出一个中间状态

循环常要维护一份正在构建的结果。例如求平均值时，可以累计有效读数的和以及条数，全部读完再相除。每轮处理后，累计值只反映已经处理的部分。先说明这一点，就容易检查初始值和更新位置。

```python
readings = [12, None, 18, 15]
total = 0
count = 0

for value in readings:
    if value is None:
        continue
    total += value
    count += 1

if count:
    print("有效条数", count)
    print("平均值", total / count)
else:
    print("没有可用读数")
```

| 已处理的元素 | 和 | 条数 |
| --- | --- | --- |
| 暂无 | 0 | 0 |
| 12 | 12 | 1 |
| 12、空值 | 12 | 1 |
| 12、空值、18 | 30 | 2 |
| 12、空值、18、15 | 45 | 3 |

每一轮之后，“和与条数只统计了已读到的有效值”都成立。这样的关系称为循环不变式。将所有值改为缺失后，程序会进入“没有可用读数”的分支，计算平均值之前就处理了条数为零的情形。

### 按键累计并保留所需信息

输入是“地点、读数”组成的记录时，可以按地点组织结果。第 2 章的 `setdefault()` 可以在地点第一次出现时建立列表。循环负责重复取记录，字典负责找到对应列表。

```python
samples = [("东站", 18), ("西站", 20), ("东站", 21)]
by_station = {}

for station, value in samples:
    values = by_station.setdefault(station, [])
    values.append(value)

print(by_station)
```

得到的东站读数是 `[18, 21]`。如果只需要各地点的条数，可用 `counts[station] = counts.get(station, 0) + 1`。在设计循环前，先决定最后需要保留全部记录，还是只需要累计值。

## 3.7 从迭代到推导式和结构匹配

### 可迭代对象与迭代器

调用 `iter` 会取得一个迭代器，再调用 `next` 就会取出下一项。迭代器记住取到哪里。耗尽时，`next(iterator)` 会抛出 `StopIteration`，而 `next(iterator, 默认值)` 会返回给定的默认值。平常用 `for` 就能自动完成获取和停止的过程。

```python
colors = ["蓝", "绿"]
cursor = iter(colors)
print(next(cursor))
print(next(cursor))
print(next(cursor, "取完了"))
print(list(colors))
```

最后一行重新遍历原列表，仍得到两项。如果继续用原来的 `cursor`，它仍停在末尾。

同一列表可以分别交出两个迭代器，两个迭代器有自己的读取位置。某些对象本身就是迭代器，例如已经创建的 `zip(...)` 结果。把它交给第二个循环时，第二个循环只会拿到尚未消费的部分。若需要反复读同一批结果，可以先转成列表。

### 用推导式直接生成容器

推导式把逐项转换和可选的筛选写在一起。列表推导式使用方括号，集合推导式使用花括号，字典推导式在花括号中给出键和值。需要同时维护几份状态、选择多条处理路径时，普通循环能明确写出每次更新的时机。

```python
readings = [-1, 4, 9, 4]
valid = [value for value in readings if value >= 0]
unique = {value for value in valid}
squares = {value: value ** 2 for value in valid}
print(valid)
print(sorted(unique))
print(squares)
```

推导式可以从展开的循环读回去。`[value * 2 for value in readings if value >= 0]` 先逐项取值，再用条件决定是否保留，最后计算要加入列表的值。右边的表达式每保留一项才求值。比如 `[100 // value for value in readings if value > 0]` 会先排除零，再做除法。

### 用 match 识别数据形状

如果输入包含不同形状的记录，`match` 可以在识别结构时提取其中的值。按顺序尝试各个 `case`，执行第一个模式匹配且附加条件成立的分支。最后的 `case _` 可以接收其余情况。

```python
for command in ["缩放 3", "查看", "缩放", "缩放 大"]:
    match command.split():
        case ["缩放", factor] if factor.isdecimal():
            print("设置倍率", int(factor))
        case ["查看"]:
            print("查看设置")
        case _:
            print("无法识别", command)
```

这里的模式同时约定首项的值和列表的长度，`factor` 取得第二项，再由 `if` 检查它的内容。[Python 官方教程的流程控制章节](https://docs.python.org/3.12/tutorial/controlflow.html)

## 3.8 回到案例 批量处理报名

用 `for` 按到达顺序取请求。空学号在清理后立即回执，并用 `continue` 进入下一轮。其余请求通过一组互斥分支确定回执，只有“通过”分支写入名单。每轮结束后都应满足两条规则，已登记的学号互不重复，人数不超过容量。这样的条件称为不变式。

```python
capacity = 2
requests = ["S01", " ", " S02 ", "S03", "S01"]
roster = {}

for number, raw_id in enumerate(requests, start=1):
    student_id = raw_id.strip()
    if not student_id:
        print(number, "（空白）", "空学号")
        continue

    if student_id in roster:
        status = "重复"
    elif len(roster) >= capacity:
        status = "满员"
    else:
        roster[student_id] = "已报名"
        status = "通过"

    print(number, student_id, status)

print("最终名单", list(roster))
print("剩余名额", capacity - len(roster))
```

| 步骤 | 学号 | 回执 | 处理后的名单 |
| --- | --- | --- | --- |
| 1 | S01 | 通过 | S01 |
| 2 | 空白 | 空学号 | S01 |
| 3 | S02 | 通过 | S01、S02 |
| 4 | S03 | 满员 | S01、S02 |
| 5 | S01 | 重复 | S01、S02 |

对照表格核对每一步。第 4、5 步都发生在满员之后，回执却不同，因为第 5 步先满足了重复条件。名单及余量由各轮的更新逐步得出。

### 根据新旧状态核对每次处理

这段流程只从“通过”分支写入字典。某轮开始时，容量的判断依据是已有名单的长度。某轮结束时，名单可能多一人，也可能保持原样。下一轮读取的是已经更新的名单，因此同一学号稍后出现时会变成重复。

| 待检查的初始状态或请求 | 对回执的预期 | 对名单的预期 |
| --- | --- | --- |
| 请求列表为空 | 没有逐条回执 | 名单保持初始状态 |
| 只剩一个名额，收到新学号 | 通过 | 新增一人，剩余名额为零 |
| 满员后收到另一个新学号 | 满员 | 没有新增 |
| 满员后收到已登记学号 | 重复 | 没有新增 |
| 学号只包含空白 | 空学号 | 不写入空键 |

可以先用这张表预测每种输入。流程变长时，把可独立验证的资格检查、单次登记和批量处理写成不同能力，会更容易定位规则发生变化的位置。[第 4 章 第三视角 函数与协作封装](04.md)
