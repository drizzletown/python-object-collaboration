# 对象协作的可靠性
> 在输入和协作边界处理预期失败，用测试、调试和日志定位规则偏差。

## 7.1 把预期失败留在合适的边界
满员是一次正常报名请求可能得到的业务回执。无法把容量输入转换成整数，是调用者可以修正的输入错误。用返回值表达前一类结果，用异常表示函数无法按契约产生结果。捕获异常时，尽量把 try 的范围缩到预期失败的语句，避免把同类的编程错误也一起吞掉。

```python
def parse_capacity(raw: str) -> int:
    try:
        capacity = int(raw)
    except ValueError as error:
        raise ValueError("容量应填写整数") from error
    if capacity < 0:
        raise ValueError("容量不能为负数")
    return capacity

for sample in [" 2 ", "-1", "两个"]:
    try:
        value = parse_capacity(sample)
    except ValueError as error:
        print(f"填写失败：{error}")
    else:
        print(f"有效容量：{value}")
```

异常会沿调用链传播，直到找到能处理它的 except。raise ... from ... 保留错误原因，便于调试。else 只在 try 正常完成时运行；finally 负责无论成功或失败都要执行的清理。对于文件等资源，第 8 章会用 with 表达清理约定。

## 7.2 用边界用例检验规则
名额只剩一个时，通过后应恰好满员。满员之后的重复请求仍应优先返回重复。空学号和容量为 0 也要单独检查。除了验证返回值，还应验证请求失败后名单仍符合契约。测试用独立名单，确保结果不依赖执行顺序。

```python
import unittest

def register(student_id, roster, capacity):
    if student_id in roster:
        return "重复"
    if len(roster) >= capacity:
        return "满员"
    roster.add(student_id)
    return "通过"

class RegistrationTests(unittest.TestCase):
    def test_duplicate_at_capacity(self):
        roster = set()
        self.assertEqual(register("S01", roster, 1), "通过")
        self.assertEqual(register("S01", roster, 1), "重复")
        self.assertEqual(register("S02", roster, 1), "满员")
        self.assertEqual(roster, {"S01"})

    def test_zero_capacity(self):
        roster = set()
        self.assertEqual(register("S01", roster, 0), "满员")
        self.assertEqual(roster, set())

suite = unittest.defaultTestLoader.loadTestsFromTestCase(RegistrationTests)
unittest.TextTestRunner().run(suite)
```

assert 可表达开发期间应当成立的内部断言，解释器开启优化时可能跳过它。表单输入与文件内容的检查应使用显式条件和异常。unittest 的断言方法会报告期望值与实际值。上例聚焦容量与重复的优先级，外部调用已清理空白学号。

## 7.3 从失败定位原因
先重现错误并记录最小输入。读取回溯末尾的异常类型和消息，再向上定位自己写的代码。使用断点停在发生变化的地方，检查名单长度、当前学号以及即将执行的分支。日志可记录时间、操作和结果，用 logging.getLogger(__name__) 获取模块日志器，把日志格式和级别交给入口设置。活动编号和回执足以定位许多问题，无需记录参加者的姓名或整份名单。
