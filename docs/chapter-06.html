多对象协作与程序组织

将活动规则、活动查询和报名请求分给不同角色，用小型接口把它们接起来。

6.1 按变化原因分配职责

现在系统有多个活动，收到的请求同时含活动编号和学号。活动对象检查它自己的规则。目录按活动编号查找活动。报名服务组织“查询活动、尝试登记、返回回执”。显示端负责把回执转换为用户看得懂的文字。新增一种显示方式时，只需依赖回执的契约。

一个对象持有另一个对象并调用它的能力，是对象组合。EnrollmentService 接收外部构造的字典，便于用只有一个活动的字典测试。调用方负责建立活动编号的唯一性。这里用 list 演示名单，第 5 章中更完整的 Activity 可以承担同样的角色。

6.2 划定模块边界


一个 .py 文件通常就是一个模块。一组按主题组织的模块可放进包中。初学时可用带 __init__.py 的普通包。将本例拆为 campus/activity.py（Activity）、campus/service.py（Request 和 EnrollmentService）及 campus/__main__.py（构造活动并显示结果）。在 service.py 使用 from .activity import Activity。在项目父目录运行 python -m campus，解释器执行包中的 __main__.py。


拆分后的目录示例见下方。先把示例中的类按职责分别移入两个模块，再让入口构造对象并调用 submit。把同一个 Request 送给正式目录和只含一项活动的测试目录，可以在真实目录尚未准备好时兑现查询接口。


campus/
  __init__.py
  __main__.py
  activity.py
  service.py


导入模块时会执行顶层语句。把演示代码放在 main() 中，再用 if __name__ == "__main__": 调用它，能够让别人导入类或函数进行测试。保持依赖方向清楚：服务可以导入领域对象，领域对象无需导入服务。若两个模块相互导入，先检查共享数据类型或职责是否放错了位置。


练习


给服务添加实验室活动并设容量为 1。提交同一学号到两个活动，随后再次向实验室提交这个学号。预测三次回执。
