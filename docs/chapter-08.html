8.1 关闭报名程序以后，名单在哪里

前几章的活动对象把名单保存在内存中。组织者结束本次工作后，下次打开程序还需要继续使用同一份名单。另一个需求是把名单交给负责签到的同学，在表格软件里查看。

  • 输入是一场已登记 S01、S02 的博物馆活动，容量为 2。
  • 保存活动名称、容量和报名顺序。恢复时从保存的记录重新取得这些数据，并验证名额与名单规则。
  • 另外生成一份有表头的名单，每位参加者占一行，供表格软件导入。

这两份文件服务于不同任务。恢复时需要保留有名字的字段及其关系，导出时需要有稳定的行和列。先了解 Python 怎样使用文件资源和两种常见的数据格式。

8.2 用路径定位外部资源

路径怎样指向一个位置

pathlib.Path 表示文件系统中的路径。绝对路径从系统规定的位置开始，相对路径通常以当前工作目录为基准。Path.cwd() 返回当前工作目录。用 / 可以拼接路径段，path.parent 取得父目录。若需要创建中间目录，可用 mkdir(parents=True, exist_ok=True)。

先构造路径，再使用路径

路径对象可以描述一个尚未创建的文件。path.name 取得最后一段文件名，path.suffix 取得扩展名，path.stem 取得去掉最后一个扩展名的名称。拼接路径只是计算位置，创建目录、打开文件是另外的操作。

8.7 在边界区分缺失、格式错误与非法数据


能打开文件、能解析格式、数据符合应用约定，是三个要分别验证的条件。例如，JSON 能把 {"quantity": -1} 解析为字典，使用库存数据的程序还需检查数量是否合法。


情形可能出现的异常调用者如何使用这个信息
路径没有对应的文件FileNotFoundError首次启动时可按约定建立初始状态
当前操作没有足够权限PermissionError报告哪个资源无法访问
字节无法按指定编码解读UnicodeDecodeError确认文件编码，保留原文件供检查
JSON 文本格式有误json.JSONDecodeError报告文件内容无法解析
数据类型或取值违反业务规则校验函数报告的 ValueError报告具体字段或规则


只有确实缺失时才启用初始数据

其他外部接口也需要说明交付条件


同样的协作思路也适用于其他外部接口。先约定如何取得资源、结果是什么格式，再判断结果能否进入业务流程。例如，调用网络服务读取数据时，调用方需要处理超时，并校验响应所带的字段。


协作步骤读取文件向服务请求数据
指定资源文件路径地址与查询条件
取得内容文本或字节响应状态和内容
解释数据解码、解析 JSON 或 CSV根据约定的格式解析响应
检查与使用校验字段后恢复状态校验字段后继续业务步骤
处理失败区分缺失、权限和坏数据区分超时、失败状态和坏数据


可以先用已知的样本文字验证解析，再接上外部读取。这会让测试依赖可控的输入，出错时也能区分是没有拿到内容，还是内容不符合约定。

练习


  • 给 CSV 增加“签到”列，默认填“未签到”。在临时目录块内用 csv.DictReader 读取第一条记录，检查两列的值。
  • 把示例活动的容量改为 1，指出程序在哪一步拒绝写入。
  • 把 load_readings() 示例写入的损坏文字换成合法的 {"values": "18"}。预测能否解析，说明还缺哪项检查。
  • 在临时文件替换示例中，改为让第二次写入也使用列表。预测最终文件与最初保存的内容是否相同。


参考解答
表头追加“签到”，数据行追加“未签到”。打开 CSV 时指定 encoding="utf-8" 和 newline=""，取 next(csv.DictReader(stream))，结果的“学号”是 S01，“签到”是未签到。
容量为 1 时，validate_event 会报告报名人数超过容量。此时程序尚未打开文件，JSON 文件还没有创建。
JSON 可以解析出字典，但 values 对应的是字符串。需要检查字段是否为列表，再检查其中的每个读数。
第二次写入使用列表时可以完成序列化和替换。若继续运行第三次写入，最终文件仍保存 [18, 20]，与最初的 [18] 不同。
